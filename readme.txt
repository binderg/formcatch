Point any HTML or PHP form at a generated endpoint. FormCatch stores, searches, and emails every submission. No shortcodes, no form builder.

== Description ==

FormCatch is a form backend, not a form builder. You write the HTML — by hand,
from a theme template, or generated by an AI assistant — and point its `action`
at an endpoint FormCatch gives you. Everything after that (storage, search,
spam filtering, email notifications, file handling) happens inside your own
WordPress install.

Nothing is sent to a third-party form service. Submissions live in your
database, on your domain.

**Why you might want it**

* No shortcodes to learn and no drag-and-drop builder to fight.
* Schema-less: FormCatch keeps whatever fields you send, so changing your form
  never means migrating a form definition.
* Works with a normal full-page POST *or* with `fetch()`/AJAX — same endpoint,
  no configuration either way.
* Your markup stays yours. Restyle or rebuild the front end whenever you like.

**Free features**

* Unlimited forms and unlimited submissions.
* Searchable submissions inbox with statuses and CSV export.
* Composable email rules per form, with {{placeholder}} templating and
  autoresponders.
* File uploads, stored outside the web root and served over signed, expiring
  links.
* CAPTCHA: Cloudflare Turnstile, hCaptcha, and Google reCAPTCHA v2/v3.
* Spam protection: honeypot, disposable-email blocking, per-form domain
  allowlist, per-IP rate limiting.
* Event log for every submission, email, and webhook, with automatic pruning.
* Configurable retention windows for GDPR-style data minimization.
* Developer hooks and filters throughout.

**Pro features**

Two features require a Pro license ($49 once, lifetime, unlimited sites):

* **Webhooks** — POST each submission to Slack, Zapier, Make, n8n, or your own
  service, optionally HMAC-signed.
* **REST / Forms API** — read submissions and create, update, or delete forms
  programmatically, including a self-describing schema endpoint for AI agents.

Pro is additive. Nothing is removed from the free plugin to make room for it,
and the public submit endpoint is never gated.

== Installation ==

1. Install and activate the plugin (Plugins > Add New, or upload the zip).
2. Go to **FormCatch > Forms > Add New**, give the form a name, and save.
3. Copy the generated endpoint URL shown on the edit screen.
4. Set that URL as the `action` attribute of your `<form>` (see Quick start
   below for a complete example).
5. Submit the form once to confirm it arrives under **FormCatch >
   Submissions**.

No further code is required. FormCatch creates its own database tables on
activation and removes them on deletion only if you explicitly opt in under
Settings.

== External services ==

FormCatch contacts the following third-party services. All of them are optional
except Freemius, which handles licensing.

**Freemius** — licensing, plugin updates, and (for Pro) checkout. The Freemius
SDK is bundled with the plugin and contacts `freemius.com` to validate a
license and check for updates. Anonymous usage data is only sent if you opt in
during activation.
Terms: https://freemius.com/terms/ — Privacy: https://freemius.com/privacy/

**Google reCAPTCHA** — only when you select reCAPTCHA as your CAPTCHA provider
in Settings. On each submission the visitor's CAPTCHA token is sent to
`https://www.google.com/recaptcha/api/siteverify` for validation, and the
widget script is loaded from `https://www.google.com/recaptcha/api.js`.
Terms: https://policies.google.com/terms — Privacy: https://policies.google.com/privacy

**hCaptcha** — only when you select hCaptcha as your CAPTCHA provider. The
visitor's token is sent to `https://api.hcaptcha.com/siteverify`, and the
widget script is loaded from `https://js.hcaptcha.com/1/api.js`.
Terms: https://www.hcaptcha.com/terms — Privacy: https://www.hcaptcha.com/privacy

**Cloudflare Turnstile** — only when you select Turnstile as your CAPTCHA
provider. The visitor's token is sent to
`https://challenges.cloudflare.com/turnstile/v0/siteverify`, and the widget
script is loaded from `https://challenges.cloudflare.com/turnstile/v0/api.js`.
Terms: https://www.cloudflare.com/website-terms/ — Privacy: https://www.cloudflare.com/privacypolicy/

**disposable-email-domains (GitHub)** — only when "Block disposable emails" is
enabled in Settings. FormCatch downloads a plain-text blocklist from
`https://raw.githubusercontent.com/disposable-email-domains/disposable-email-domains/main/disposable_email_blocklist.conf`
when the plugin updates, or when you refresh it manually. No data about your
site or your visitors is sent — it is a one-way download.
Terms: https://docs.github.com/site-policy/github-terms/github-terms-of-service — Privacy: https://docs.github.com/site-policy/privacy-policies/github-privacy-statement

**Webhooks (Pro)** — when you configure a webhook URL, submission data is sent
to whatever destination *you* choose. FormCatch does not pick that destination
and sends nothing anywhere unless you configure it.

== Quick start ==

1. Activate the plugin.
2. Go to FormCatch > Forms > Add New. Give it a name, save.
3. Copy the generated endpoint URL shown on the edit screen.
4. Set that URL as the `action` attribute of your `<form>`:

   <form action="https://yoursite.com/wp-json/formcatch/v1/submit/{token}" method="post">
       <input type="text" name="name">
       <input type="email" name="email">
       <textarea name="message"></textarea>
       <input type="text" name="{honeypot_field}" style="display:none" tabindex="-1" autocomplete="off">
       <button type="submit">Send</button>
   </form>

5. That's it — no further code required. FormCatch accepts whatever
   fields you send (schema-less) and stores them as-is.

Submitting the form normally (full page POST) redirects back to the
referring page with `?submitted=1`, or to a custom Redirect URL you set
per-form. Submitting via `fetch()`/AJAX with `Accept: application/json`
gets a JSON response instead — same endpoint, no configuration needed
either way.

== Per-form settings ==

Organized into tabs on the form edit screen:

- General — form name, active/disabled status, save-to-database, redirect URL.
- Email — one or more email rules, each with recipients, subject, body,
  plain/HTML format, and an optional Reply-To field. Subject/body/recipients
  support {{placeholders}} (see below). Set a rule's "Send to" to {{email}}
  to turn it into an autoresponder back to the submitter.
- Spam — honeypot field name, CAPTCHA (if configured globally), and whether
  to notify on spam-flagged submissions.
- Advanced — webhook URL(s) (Pro).

== Email placeholders ==

Usable in an email rule's recipients, subject, and body:

- {{field_name}} — any submitted field value (e.g. {{email}}, {{name}}).
- {{form_name}} — the form's name.
- {{submission_id}} — the stored submission ID.
- {{all_fields}} — every submitted field formatted as a list.
- {{files}} — download links for any files attached to the submission.

Unknown placeholders are left visible (not blanked) so typos are obvious.

== Webhooks (Pro) ==

Per form, POST each non-spam submission to one or more URLs (Slack, Zapier,
etc.) as JSON. Optionally sign requests with an HMAC secret (Settings) — the
signature is sent in the X-FormCatch-Signature header so receivers can verify
authenticity. Every webhook attempt is recorded in the Logs screen with its
HTTP status.

== CAPTCHA ==

Configure keys once in Settings (Cloudflare Turnstile, Google reCAPTCHA v2, or
reCAPTCHA v3), then enable per form on its Spam tab. FormCatch generates the
exact widget markup to paste into your form. reCAPTCHA v3 supports a per-form
badge position (bottom-right / bottom-left / inline).

== Logs ==

Every submission received, email sent, and webhook fired is recorded with a
status (success / error / skipped) and searchable context. Failed events raise
a dismissible admin notice and a count badge on the Logs menu. Logs auto-prune
after a configurable retention window (default 90 days).

== CORS ==

For cross-domain fetch()/AJAX submissions, add allowed origins in Settings
(one per line, or * for any). Same-origin submissions always work.

== REST API (Pro) ==

Read stored submissions programmatically. Free installs receive HTTP 402 on
these endpoints; the public submit endpoint (/submit/{token}) is always free.

Endpoints:

- GET /wp-json/formcatch/v1/submissions
  Query params: form_id, status (new|read|spam), search, page (default 1),
  per_page (default 20, max 100). Responses include X-WP-Total and
  X-WP-TotalPages headers for pagination.

- GET /wp-json/formcatch/v1/submissions/{id}
  A single submission.

Response shape (per submission):

  {
    "id": 12,
    "form_id": 3,
    "status": "new",
    "data": { "name": "Ada", "email": "ada@example.com" },
    "ip": "203.0.113.7",
    "referrer": "https://example.com/contact",
    "created_at": "2026-07-06 14:22:01"
  }

Authentication:

There is no separate FormCatch API key. Access is gated by the same
WordPress capability that manages the plugin (manage_options by default,
filterable via `fc_manage_capability`), using WordPress's built-in REST
authentication. Anonymous or under-privileged requests get HTTP 401.

Two ways to authenticate:

1. Cookie + nonce — for calls from an admin's own browser session. Send the
   REST nonce in the X-WP-Nonce header (wp_create_nonce( 'wp_rest' )).
   This is how in-dashboard JavaScript authenticates.

2. Application Passwords — for external scripts/servers. In WordPress, go to
   Users > Profile > Application Passwords, generate one for a user who has
   the manage capability, then use HTTP Basic Auth:

     curl -u "admin:xxxx xxxx xxxx xxxx" \
       "https://yoursite.com/wp-json/formcatch/v1/submissions?form_id=3"

The submissions API is read-only. Creating submissions is done through the
public submit endpoint (/submit/{token}); there is no write API for editing
stored rows. Forms, by contrast, are fully writable via the Forms API
(/forms, /forms/{id}, /forms/schema, /forms/import).

== Developer hooks ==

- `fc_manage_capability` (filter) — change which capability is required to manage FormCatch (default `manage_options`).
- `fc_after_submission_saved` (action) — `( $form, $payload, $submission_id, $is_spam )`, fires after every submission is processed.
- `fc_email_subject` / `fc_email_body` / `fc_email_headers` / `fc_email_tokens` (filters) — customize the notification email.
- `fc_webhook_payload` / `fc_webhook_headers` (filters) — customize the webhook request.
- `fc_redirect_url` (filter) — override the redirect target on non-JSON submissions.

== Notes ==

- Rate limiting is a simple per-IP-per-form transient counter (default 10/min), configurable in Settings.
- A max-fields-per-submission cap (default 100) rejects oversized payloads.
- Deactivating the plugin never touches your data. Deleting it only removes data if you've explicitly opted in under Settings.
- Search on the Submissions and Logs screens matches stored values with LIKE (not a full-text index) — fine at the volumes this plugin targets, but not built for tens of thousands of rows.
